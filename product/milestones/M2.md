# M2 — Theatre Seeding Pipeline

- **Status:** Not started
- **Repos:** `goldseats-api`
- **Depends on:** [M1](M1.md)
- **Blocks:** [M4](M4.md), [M5](M5.md)

> **Done when:** a seeded theatre renders a correct seat grid via API and each showtime carries
> a valid outbound booking URL.

---

## Goal

Get real auditoriums into the database. Not synthetic ones, not approximations — actual
seating configurations for 5 to 10 real Canadian auditoriums, hand-authored from public floor
plans and seating charts, with geometry produced by the same code that generated the layouts
the scoring model was tuned against.

This milestone is where GoldSeats stops being a catalog and starts being a product about
seats. It's also the milestone with the highest ratio of careful data work to code, and the
one where cutting corners would quietly invalidate everything [M5](M5.md) builds.

---

## Scope

- Versioned `seat_layout` JSON schema with its own `schema_version`
- Models: `theatres`, `auditoriums`, `seat_layouts`, `seats`, `showtimes`,
  `showtime_formats`, `booking_links`, `seat_availability_snapshots`
- `app/cli/seed_theatre.py` — idempotent admin seeding CLI
- 5 to 10 hand-seeded real auditoriums, geometry from `generator/theatre.py`
- Hand-seeded showtimes with formats, languages, and validated booking links
- Simulated availability snapshots from the dataset generator's booking simulator
- Endpoints: theatres, auditoriums, seat layout, showtimes, seat availability
- Switch "now playing" from `film_releases` to "has a future showtime"

## Out of scope

- Any scoring or recommendation — [M5](M5.md)
- The 2D seat map UI — [M5](M5.md)
- Real-time or partner availability data — needs a partnership, see
  [ADR-0003](../../architecture/adr/0003-manual-seed-theatre-data.md)
- **Scraping. Ever.** Not deferred; excluded.
- Automated showtime ingestion
- Coverage beyond the Greater Toronto Area

## Issue breakdown

### Schema and models

- [ ] Design the `seat_layout` JSON schema: screen dimensions, geometry, aisles, rows, seats
- [ ] JSON Schema file plus a Pydantic validator, `schema_version` 1
- [ ] Migration: `theatres`, `auditoriums`
- [ ] Migration: `seat_layouts`, `seats`
- [ ] Migration: `showtimes`, `showtime_formats`, `booking_links`
- [ ] Migration: `seat_availability_snapshots`
- [ ] Enforce exactly one `is_current` layout per auditorium in application code (a partial
      unique index would break SQLite)
- [ ] `uq_showtimes_auditorium_id_starts_at` — one auditorium can't run two films at once
- [ ] `CHECK` on `seat_availability_snapshots.source` permitting only `manual`, `simulated`,
      `partner_api`. **No `scraped` value** — the policy as a constraint.
- [ ] All `ondelete` behaviours per the cascade table in the data model
- [ ] Downgrades for every migration, round-trip tested, on both engines

### Geometry, shared with the dataset generator

- [ ] Extract the coordinate maths from `ml/dataset/generator/theatre.py` into a shared module
      importable by both the generator and the seeding CLI
- [ ] Verify a generated `standard` layout and a seeded `standard` layout produce **identical
      coordinates** for the same row/seat configuration. This is the issue that protects
      [M5](M5.md)'s score validity.
- [ ] Support all five kinds: `standard`, `large`, `small`, `imax`, `recliners`
- [ ] Handle row curvature, stadium rise, aisle gaps, and the IMAX premium centre section
- [ ] Unit tests asserting geometric invariants: symmetric about the centreline, monotonic
      elevation, aisle seats flagged correctly

### Seeding CLI

- [ ] `python -m app.cli.seed_theatre --file <path>`
- [ ] `--all` to seed every file in `seeds/`
- [ ] `--dry-run` printing what would change without writing
- [ ] Idempotent: upsert on `theatres.slug` and `(auditorium, version)`
- [ ] Project `layout_json` into `seats` rows — never hand-author `seats`
- [ ] Validate against the JSON schema before writing; refuse a bad file with a useful error
- [ ] Record `seeded_by`, `seeded_at`, `source_file`, and `notes` on every layout
- [ ] Creating a new layout version flips `is_current` atomically
- [ ] Human-readable summary: theatre, auditoriums, rows, seats, showtimes

### Seed the real data

- [ ] Choose 5–10 auditoriums. Bias toward high-traffic GTA Cineplex locations with published
      seating charts and a mix of `standard`, `imax`, `recliners`, and `vip`.
- [ ] For each: author the layout from public floor plans and published seating charts,
      cross-check against the chain's own seat picker rendering, record where every measurement
      came from in `notes`
- [ ] Measure or estimate screen width, screen height, screen bottom height, and first-row
      distance. Estimates are marked as estimates in `notes`.
- [ ] Seed `theatres` with real addresses, coordinates, and `America/Toronto` timezone
- [ ] Seed two weeks of showtimes for the seeded auditoriums, with formats and presentation
      languages
- [ ] Seed `booking_links` per showtime; verify every URL resolves and record
      `last_verified_at`
- [ ] Verify seat counts against the published capacity for each auditorium

### Booking links

- [ ] `url_template` supporting `{row}` and `{seats}` placeholders
- [ ] `supports_seat_preselection` per provider, honestly recorded
- [ ] `allowed_host` on every row, **validated against a hardcoded allowlist at render time**,
      not only at seed time
- [ ] Test: a link whose host isn't on the allowlist is refused, not rendered
- [ ] `link_kind` distinguishing `online_purchase`, `showtime_page`, `theatre_page`

### Availability

- [ ] Adapt the booking simulator from `ml/dataset/generator/seats.py` to write
      `seat_availability_snapshots`
- [ ] Occupancy varies plausibly by time of day and days-until-showtime
- [ ] Always `source='simulated'`, `confidence='low'`
- [ ] `GET /v1/showtimes/{id}/seat-availability` returns the latest snapshot **with its
      `source` and `confidence`**, so the client can be honest
- [ ] `Cache-Control: no-store` on availability
- [ ] Pruning job for snapshots older than 30 days

### Endpoints

- [ ] `GET /v1/theatres` with `?near=lat,lng&radius_km=`
- [ ] `GET /v1/theatres/{theatre_id}` and `/auditoriums`
- [ ] `GET /v1/auditoriums/{auditorium_id}/seat-layout` — full geometry, 24-hour cache
- [ ] `GET /v1/showtimes` with `film_id`, `theatre_id`, `date`, `format`, `language` filters
- [ ] `GET /v1/showtimes/{showtime_id}` embedding auditorium, theatre, formats, booking links
- [ ] Showtime responses carry `starts_at` (UTC), `starts_at_local`, and `timezone`
- [ ] **Switch `/v1/films/now-playing` to "has a future showtime"** and update its description
- [ ] Eager-load everything serialised; query-count tests

## Risks

| Risk | Likelihood | Mitigation |
| --- | --- | --- |
| **Seeded geometry diverges from training geometry**, silently invalidating every score | Medium, severe | Shared geometry module plus an explicit equality test between generated and seeded layouts. The highest-value issue in this milestone. |
| Published seating charts are inaccurate or out of date | Medium | Cross-check against the chain's live seat picker; record provenance in `notes`; verify total seat count against published capacity |
| Screen dimensions unavailable for some auditoriums | High | Estimate from auditorium kind and published capacity, **mark as estimated in `notes`**, and prioritise verifying the ones where the view-angle factor is most sensitive |
| Simulated availability presented as real | Medium, reputational | `source` and `confidence` are non-null columns, returned by the API, and the UI is required to disclose them. Enforced in [M5](M5.md)'s definition of done. |
| Hand-seeded showtimes go stale within a week | Certain | Accepted for M2. It's the known ceiling on this approach and the trigger for revisiting [ADR-0003](../../architecture/adr/0003-manual-seed-theatre-data.md). |
| Booking URLs change structure without notice | Medium | `last_verified_at`, a periodic verification pass, and graceful degradation to the theatre page |
| Booking link becomes an open redirect | Low, serious | `allowed_host` validated against a hardcoded allowlist at render time |
| Timezone bugs in showtimes | High | Three columns (`starts_at`, `starts_at_local`, `timezone`), tests covering DST boundaries in `America/Toronto` |
| Seeding 10 auditoriums takes far longer than estimated | High | Start with 5. The done-when criterion says 5–10, and 5 correct auditoriums beats 10 sloppy ones. |

## Done when

**A seeded theatre renders a correct seat grid via API and each showtime carries a valid
outbound booking URL.**

Verified by:

```bash
python -m app.cli.seed_theatre --all
curl 'localhost:8000/v1/theatres?near=43.6532,-79.3832&radius_km=25'
curl 'localhost:8000/v1/auditoriums/<id>/seat-layout'   # row/seat counts match published capacity
curl 'localhost:8000/v1/showtimes?theatre_id=<id>'      # every showtime has a booking_links entry
curl 'localhost:8000/v1/showtimes/<id>/seat-availability'
```

"Correct" means a human compares the returned grid against the theatre's published seating
chart and they match — row labels, seat numbers, aisle positions, and total count. And every
booking URL, opened in a browser, lands on the right showtime.
