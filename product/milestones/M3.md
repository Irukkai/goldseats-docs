# M3 — Web Shell and Home Page

- **Status:** Not started
- **Repos:** `goldseats-web`
- **Depends on:** [M1](M1.md) (contract only)
- **Blocks:** [M4](M4.md), [M5](M5.md)

> **Done when:** home page is live against the real API with working filters and Lighthouse
> above 90.

---

## Goal

Build the web application GoldSeats actually looks like. Migrate the finished landing page in
as the marketing route, extract its gold-on-dark palette into Tailwind design tokens, build a
shared UI kit, and ship a home page that lists what's playing and what's coming with the
filters the product promises.

This can run in parallel with [M2](M2.md), once [M1](M1.md) freezes the API contract. The home
page is built against the contract; the data behind it gets better as [M2](M2.md) lands.

---

## Scope

- Next.js 16 App Router project structure with `(marketing)` and `(app)` route groups
- `tailwind.config.ts` carrying the `ink` and `gold` token scales from `index.html`
- Self-hosted Inter and Playfair Display via `next/font`
- Shared UI kit: `Button`, `Card`, `Skeleton`, `Select`, `Badge`, `Input`, `EmptyState`
- The existing 876-line landing page migrated into the marketing route group
- Home page: currently playing and upcoming, with title, release-date, and language filters
- Server components with explicit caching, `loading.tsx` skeletons, `error.tsx` boundaries
- Full mobile responsiveness at 375 / 768 / 1440
- Generated API types from the OpenAPI schema
- Lighthouse CI as a blocking check

- Seat map — [M5](M5.md)

- Chat UI — [M7](M7.md)

## Issue breakdown

### Project setup

- [ ] Route groups: `(marketing)/page.tsx`, `(app)/page.tsx`, shared `app/layout.tsx`
- [ ] Root layout: `lang`, metadata, "skip to main content", dark theme by default
- [ ] `next/font` for Inter and Playfair Display, subset to Latin + Latin-Ext,
      `font-display: swap`
- [ ] `tailwind.config.ts`: `ink.950 #0a0a0f`, `ink.900`, `ink.800`, `ink.200`,
      `gold.400/500/600`, plus the display font family
- [ ] `src/lib/env.ts` with zod validation
- [ ] `npm run generate:api-types` against the API's `/openapi.json`
- [ ] `src/lib/api/client.ts` — `fetch` wrapper, `ApiError`, `X-Request-Id` forwarding

### Migrate the marketing page

- [ ] Port `index.html` into `(marketing)/page.tsx` as components: `Hero`, `SocialProof`,
      `HowItWorks`, `WhyGoldSeats`, `WaitlistForm`, `Footer`
- [ ] Convert inline CSS to Tailwind using the tokens. **No raw hex values.**
- [ ] Animated seat-grid hero background as CSS/SVG, respecting `prefers-reduced-motion`
- [ ] "Golden Seat Score: 98/100" pulse pill, motion-respecting
- [ ] Replace the Font Awesome kit with six inline SVG social icons
- [ ] Waitlist form: keep the Formspree action, wire the real form ID, add proper labels,
      error states, and a success state
- [ ] Move the in-page privacy section to a real `/privacy` route rendering
      [`../../legal/privacy-policy.md`](../../legal/privacy-policy.md)
- [ ] Visual comparison against the original at 375 / 768 / 1440

### UI kit

- [ ] `Button` — primary (gold), secondary, ghost; sizes; loading state; focus-visible ring
- [ ] `Card` — the shared surface for film cards and panels
- [ ] `Skeleton` — shimmer respecting `prefers-reduced-motion`
- [ ] `Select` — native `<select>`, labelled
- [ ] `Input` with visible label, error text, `aria-describedby`
- [ ] `Badge` — used for formats and later for seat scores
- [ ] `EmptyState` — illustration slot, heading, body, optional action
- [ ] Every component has a Vitest test querying by role and accessible name

### Home page

- [ ] `(app)/page.tsx` server component, parallel `getNowPlaying` and `getUpcoming`
- [ ] `FilmCard` — poster with explicit dimensions, title, release date, language, runtime
- [ ] `FilmGrid` — responsive: 2 columns at 375px, 3 at 768px, 5 at 1440px
- [ ] `FilmFilters` — title text input (debounced), release-date range, language `<select>`
- [ ] Filters as a real `<form>` writing to URL search params, working without JavaScript
- [ ] Language selector reads options from the API's available languages, not a hardcoded list
- [ ] `loading.tsx` with a skeleton grid matching the real grid's dimensions — **no layout
      shift**
- [ ] `error.tsx` with human copy and a quiet `request_id`
- [ ] `EmptyState` for "no films match these filters", with a clear-filters action
- [ ] Cache: `revalidate: 900` with tags on catalog fetches

### Accessibility

- [ ] Every interactive element keyboard reachable with a visible focus ring
- [ ] Filter changes announced via a polite live region
- [ ] Poster `alt` text: "Poster for <title>"
- [ ] `lang` attribute on non-English film titles — a French title in an English page needs
      `lang="fr"` or a screen reader mispronounces it
- [ ] Contrast verified against the table in
      [`../../engineering/accessibility.md`](../../engineering/accessibility.md)
- [ ] `@axe-core/playwright` on the home page and the marketing page, zero violations
- [ ] Manual keyboard-only pass and a VoiceOver pass

### Performance

- [ ] `next/image` for posters: AVIF with WebP fallback, TMDB `w500`, explicit

- [ ] **Zero CLS from poster loading** — aspect-ratio containers on every card
- [ ] First-load JS under 120 KB on the home page, under 90 KB on marketing
- [ ] Lighthouse CI wired as a blocking check at 90 performance / 95 accessibility
- [ ] Bundle analyser in CI with the budgets from
      [`../../engineering/performance-budgets.md`](../../engineering/performance-budgets.md)

## Risks

| Risk | Likelihood | Mitigation |
| --- | --- | --- |
| Lighthouse 90 is hard to hit retroactively | High | Lighthouse CI blocking from the first page, not added at the end. Budgets are cheaper to hold than to recover. |
| Poster images cause CLS and fail the budget | High | Explicit dimensions and aspect-ratio containers as a hard rule; a Playwright CLS assertion |
| App Router caching shows stale data | Medium | Explicit cache policy on every `fetch`, reviewed. Availability and recommendations are always `no-store` — but that's [M5](M5.md). |
| Migrated marketing page drifts visually from the original | Medium | Side-by-side screenshot comparison at three widths before merge |
| Contract changes after freeze, forcing rework | Medium | Post-freeze API changes need a `BREAKING CHANGE:` footer and a linked web PR |
| Language selector implies full UI translation | Medium | Label it as a film-language filter in the UI. Translating our own chrome is a separate, later decision. |
| Accessibility retrofitted rather than built in | High | axe in CI plus manual passes as milestone deliverables, not follow-ups |
