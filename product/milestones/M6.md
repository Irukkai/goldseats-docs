# M6 — 3D View From Seat

- **Status:** Not started
- **Repos:** `goldseats-web`
- **Depends on:** [M5](M5.md)
- **Blocks:** [M9](M9.md)

> **Done when:** selecting any seat renders its 3D view at 60fps on desktop and degrades
> gracefully on mobile.

---

## Goal

Show people what they'll actually see. A score of 98 is an abstraction; a render from the
seat's eye position, with the screen at its true relative size, is a visceral answer to "is
this a good seat?"

The critical constraint is honesty. The screen must subtend the correct angle from the camera
— if we render a flattering view that's wider than reality, we've built a marketing asset
instead of a tool, and the user finds out when they sit down.

---

## Scope

- react-three-fiber auditorium scene built from the same `seat_layout` data as the 2D map
- Camera at the selected seat's eye position, using real geometry
- Screen at true relative size, so the viewing angle is honest
- Quality tiers with a capability check, including a non-3D path
- Lazy loaded so three.js never enters an initial bundle
- Text panel stating distance, horizontal angle, vertical angle, and comparison to the THX
  target
- Keyboard-operable camera

## Out of scope

- Photorealism. This is a geometric preview, not a render of the room's decor.
- Photographic textures or real auditorium photography
- Other audience members in the scene
- A 3D seat *picker*. Selection happens in the 2D map; the 3D view is a preview of a selection.
- VR or device-orientation control

## Issue breakdown

### Geometry and maths

- [ ] `lib/three/geometry.ts` — pure functions converting `seat_layout` + a selected seat into
      a camera position and target
- [ ] Eye height: seated eye level above the seat's floor elevation. Use a documented constant
      (~1.15m seated eye height above floor) and say so in a comment.
- [ ] Screen plane placed at `first_row_distance_m` from row 0, at
      `screen_bottom_height_m` above the front-row floor, with real width and height
- [ ] Horizontal viewing angle: `2 * atan((screen_width_m / 2) / distance_m)`
- [ ] Vertical viewing angle, and the vertical offset — looking up at a screen is a real
      comfort factor
- [ ] Row curvature: a curved row's seats aren't on a straight line, and the camera must
      respect that or edge seats will be wrong
- [ ] Unit tests: a centre mid-auditorium seat in a standard auditorium produces an angle near
      36°; an IMAX front-row seat produces a much larger one
- [ ] Assert the rendered screen's angular size **matches the number in the text panel**. The
      render and the facts must agree or one of them is lying.

### Scene

- [ ] `AuditoriumScene` built from `seat_layout` — rows, seats, aisles, stadium elevation,
      curvature
- [ ] **Instanced meshes for seats.** 500 seats is one draw call. Non-negotiable.
- [ ] `ScreenMesh` — emissive plane at true dimensions, with a neutral test-pattern or dimmed
      content look
- [ ] Simple room geometry: floor, side walls, ceiling. Enough for spatial sense, no more.
- [ ] Baked ambient occlusion; **no real-time shadows**
- [ ] Occupied seats visually distinct from free ones, matching the 2D map's semantics
- [ ] The selected seat's own seat back not obscuring the camera
- [ ] Scene geometry built once per `(auditorium_id, seat_layout_version)` and memoised;
      selecting a different seat only moves the camera
- [ ] `frameloop="demand"` — render on interaction, not continuously. A static preview
      redrawing 60 times a second is pure battery drain.
- [ ] Dispose geometries, materials, and textures on unmount. A leaked WebGL context after
      three seat selections crashes phones.

### Quality tiers

- [ ] Capability check on mount: WebGL support, `navigator.deviceMemory`,
      `hardwareConcurrency`, `prefers-reduced-motion`
- [ ] `high` — desktop, ≥8GB: full geometry, AO, antialiasing, DPR up to 2
- [ ] `medium` — mid mobile, 4–8GB: simplified seat geometry, no AO, DPR 1.5
- [ ] `low` — <4GB, or measured under 24fps over 2 seconds: box seats, DPR 1, static camera
- [ ] `none` — no WebGL, or reduced-motion: static image plus the text panel
- [ ] Runtime downgrade: if the measured frame rate stays under target, drop a tier and keep
      going rather than stuttering
- [ ] A visible, manual quality override so users aren't stuck with our guess
- [ ] Log the chosen tier so we learn what real devices get

### Integration and accessibility

- [ ] `SeatViewPanel` lazy loaded via `next/dynamic` with `ssr: false` and a skeleton
- [ ] Opens from the 2D map when a seat is selected; the 2D map remains fully usable without it
- [ ] `<canvas>` `aria-label` describing what it shows, including the viewing angle
- [ ] `SeatViewFacts` alongside the canvas: distance to screen, horizontal angle, vertical
      angle, and how that compares to the THX-recommended 36°. **This is an equal path, not a
      fallback** — for many users the numbers are more useful than the render.
- [ ] Keyboard camera controls: arrows to look around, `Esc` to reset
- [ ] Visible "Skip 3D preview" control; the panel never auto-focuses
- [ ] `prefers-reduced-motion` disables camera transitions and auto-movement
- [ ] Works entirely without the 3D view — the [M5](M5.md) flow is unchanged if this feature is
      off

### Performance

- [ ] Lazy chunk under 400 KB gzipped; bundle analyser check proving three.js is in no initial
      bundle
- [ ] Draw calls under 150 desktop / 80 mobile; triangles under 250k / 100k
- [ ] Time to first frame under 1.5s desktop / 3s mobile
- [ ] 60fps sustained on a mid-range desktop, measured with a real profile, not assumed
- [ ] ≥30fps sustained on a mid-range Android, on a real device
- [ ] Texture memory under 64 MB / 24 MB
- [ ] No memory growth across ten consecutive seat selections

### Testing

- [ ] Unit tests for all camera and angle maths — **the part that must be correct**
- [ ] Playwright: select a seat, canvas renders, screenshot comparison within tolerance
- [ ] Playwright: `none` tier shows the static image and the facts panel
- [ ] Manual verification on a real low-end Android
- [ ] Manual sanity check against reality: sit in a seat in a seeded auditorium and compare

## Risks

| Risk | Likelihood | Mitigation |
| --- | --- | --- |
| **The render flatters the seat** and the viewing angle isn't honest | Medium, serious | A test asserting the rendered angular size matches the text panel's number. Both derive from the same maths. |
| Estimated screen dimensions make the preview wrong | High | Mark estimated dimensions as approximate in the UI; prioritise verifying the auditoriums where the factor is most sensitive |
| Poor performance on low-end mobile | High | Four quality tiers, runtime downgrade, and a complete non-3D path. `none` is first-class. |
| three.js leaks into an initial bundle | Medium | `next/dynamic` with `ssr: false` plus a bundle-analyser check in CI |
| WebGL context leak crashes phones | Medium | Explicit disposal on unmount; a ten-selection memory test |
| Scope creep toward photorealism | High | Out-of-scope list above. The value is geometric honesty, not decor. |
| Users expect a photo and are disappointed by an abstraction | Medium | Label it plainly as a geometric preview; pair it with the numbers |
| Curved rows produce wrong camera placement for edge seats | Medium | Curvature handled explicitly in the maths, with a unit test on an edge seat |
