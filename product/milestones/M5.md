# M5 — Seat Intelligence and Booking Handoff

- **Status:** Not started
- **Repos:** `goldseats-api`, `goldseats-web`
- **Depends on:** [M2](M2.md), [M3](M3.md)
- **Blocks:** [M6](M6.md), [M7](M7.md)

> **Done when:** a user can pick a showtime, get ranked seats with scores, and land on the
> theatre's booking page.

---

## Goal

Ship the product. Everything before M5 is infrastructure; this is the milestone where
GoldSeats does the thing it exists to do.

The seat recommender already exists as `goldseats-dataset/generator/recommender.py`. M5
promotes it to `app/ml/scoring.py` as a documented, tested, versioned service; exposes it as
`POST /v1/recommendations`; renders the result as an interactive 2D seat map with golden seats
and visible scores; and ends the flow at the theatre's own booking page.

It also defines the scoring contract that [M6](M6.md) and [M7](M7.md) both build on, so the
interface matters as much as the implementation.

---

## Scope

- Promote the recommender into `app/ml/scoring.py` — pure, typed, documented, benchmarked
- `POST /v1/recommendations` and `GET /v1/recommendations/{id}`
- Scenario resolution from party size, server-side
- Golden fixture snapshot tests locking the score distribution
- Interactive 2D seat map with scores, fully keyboard accessible
- The booking fork: buy online (deep link) or reserve in person (saves the pick)
- Honest disclosure of simulated availability
- Accessible-seating support as a real filter, not a legend entry

## Out of scope

- 3D view — [M6](M6.md)
- Chatbot — [M7](M7.md), though M5's endpoint is the tool it calls
- Any actual seat holding or payment. **Permanently out of scope.** "Reserve in person" saves
  your pick; it does not hold the seat.
- Retraining or replacing the scoring model. M5 promotes and documents the existing weighted
  heuristic; it doesn't change it.
- Price comparison

## Issue breakdown

### Promote the scoring engine

- [ ] Move `generator/recommender.py` logic into `app/ml/scoring.py`
- [ ] Define the interface: `SeatGeometry` and `SeatScore` as frozen, slotted dataclasses
- [ ] `SCORING_WEIGHTS: Final[dict[str, float]]` — 0.25 / 0.25 / 0.20 / 0.15 / 0.15
- [ ] `THX_TARGET_VIEW_ANGLE_DEG: Final[float] = 36.0`
- [ ] Split into five independently testable factor functions, each returning 0.0–1.0
- [ ] `score_layout(seats, *, scenario, screen_width_m) -> list[SeatScore]`
- [ ] **Always populate `SeatScore.factors`** — [M7](M7.md)'s explanations and the map's hover
      state both depend on it
- [ ] Contiguous same-row block resolution for `pair`, `small_group`, `large_group`, `family`
- [ ] Pass unavailable seats in, not filtered out — occupied neighbours affect openness
- [ ] Return `[]` when the party cannot be seated contiguously. Not an error; a real answer.
- [ ] `SCORING_VERSION` constant, bumped on any weight or geometry change
- [ ] Google-style docstrings on every public function
- [ ] Assert no SQLAlchemy import in the module — a test, not a convention

### Scoring tests

- [ ] Per-factor tests: horizontal centre peaks at the centreline; view angle peaks near 36°
      and is penalised both directions; vertical position peaks around 50% depth; openness
      responds to occupied neighbours; row quality reflects elevation and recliners
- [ ] `test_weights_sum_to_one`
- [ ] Contiguity test: a group block is adjacent, same-row, no aisle crossing
- [ ] Empty-result test when no contiguous block exists
- [ ] Front-row test: a front row never outranks mid-auditorium for `solo`
- [ ] Golden snapshots for every seeded auditorium × five scenarios, in `tests/fixtures/golden/`
- [ ] Benchmark test per auditorium size against the budgets in
      [`../../engineering/performance-budgets.md`](../../engineering/performance-budgets.md)

### API

- [ ] `POST /v1/recommendations` — `showtime_id`, `party_size` (1–12), `preferences`
- [ ] `SeatPreferences`: `aisle_preferred`, `avoid_front_rows`, `max_walk_distance_rows`,
      `accessible_seating_required`
- [ ] Resolve scenario from `party_size` server-side; reject a client-sent scenario
- [ ] Load the current layout, project geometry, load the latest availability snapshot
- [ ] Run scoring via `anyio.to_thread.run_sync`
- [ ] Persist to `recommendations` with `seat_layout_version`, `scoring_version`,
      `seat_availability_snapshot_id`, `duration_ms`
- [ ] Response includes `options[]` with rank, score, seats, `factors`, and a human
      `explanation` generated from the factor breakdown
- [ ] Response includes `booking.online_url` and `booking.supports_in_person_reservation`
- [ ] Response includes the availability `source` and `confidence`
- [ ] Empty case: `200` with `options: []` and `empty_reason`
- [ ] `accessible_seating_required` filters to wheelchair spaces plus companion seats as a
      contiguous pair, **scored honestly** — a poor-view accessible space gets a low score
- [ ] `GET /v1/recommendations/{id}`
- [ ] `PATCH /v1/recommendations/{id}` setting `outcome` and `selected_seats_json`
- [ ] `Cache-Control: no-store`
- [ ] Redis memoisation on `(layout_version, availability_snapshot_id, scenario, preferences)`,
      60s
- [ ] `recommendation.generated` and `recommendation.failed` structured logs; metrics per
      [`../../engineering/observability.md`](../../engineering/observability.md)

### Web — seat map

- [ ] `/showtimes/[showtimeId]/seats` route with showtime header and film context
- [ ] Party-size control and preference toggles
- [ ] `SeatMap2D` rendered from `seat_layout` geometry, respecting curvature, aisles, and
      stadium rows
- [ ] `role="grid"` / `role="row"` / `role="gridcell"` semantics
- [ ] Accessible name per seat carrying row, number, availability, score, rank, seat type, and
      aisle status
- [ ] Roving `tabIndex`: one tab stop for the grid, arrows within it
- [ ] `Home`/`End` for row ends, `PageUp`/`PageDown` for first/last row
- [ ] **`G` jumps to the next golden seat.** Not in any spec; it's the most common intent and
      making it one keystroke is strictly better than what mouse users get.
- [ ] Focus lands on the top recommendation on entry, not seat A1
- [ ] Seat states carry **two signals each** — colour plus shape or glyph — per the table in
      [`../../engineering/accessibility.md`](../../engineering/accessibility.md)
- [ ] Visible legend on the page, not in a tooltip
- [ ] Golden seats get the gold halo **and** a visible score badge **and** a star glyph
- [ ] Per-factor breakdown on hover and on focus, as a small panel
- [ ] Group blocks rendered as a connected unit, so it's obvious the three seats go together
- [ ] Polite live region announcing recommendations, selection, and failures
- [ ] Touch targets ≥ 44px on touch devices; the mobile map pans and zooms rather than
      shrinking seats
- [ ] Pinch-zoom never disabled
- [ ] `no-store` on the recommendation fetch; never cache a seat map
- [ ] Skeleton while scoring; empty state with a suggestion when no block exists

### Web — booking fork

- [ ] After selection: "Book online" and "Reserve to pay in person"
- [ ] "Book online" → validate the host against the allowlist → `PATCH` the outcome →
      navigate to the theatre
- [ ] When `supports_seat_preselection` is false, show the seats to ask for at the counter
      before handing off
- [ ] "Reserve in person" → `PATCH` outcome → confirmation screen with row and seat numbers,
      showtime, theatre, and address, printable and saveable
- [ ] **Copy must never imply the seat is held.** Exact wording: "We've saved your pick. This
      doesn't hold the seats — buy at the box office to secure them."
- [ ] Simulated-availability banner whenever `confidence` is `low`, worded plainly
- [ ] `booking_handoff_total` metric split by `online` / `in_person`

### Testing

- [ ] Playwright: showtime → party size 2 → recommendations → golden seats highlighted with
      scores → book online → lands on the theatre domain
- [ ] Playwright: same up to the fork → reserve in person → pick persists across reload
- [ ] Playwright: keyboard-only completion of the whole flow
- [ ] axe clean on the seat map
- [ ] Vitest: keyboard navigation, accessible names, score-not-colour-only

## Risks

| Risk | Likelihood | Mitigation |
| --- | --- | --- |
| **Scoring drift during the promotion** — a refactor subtly changes the numbers | High | Golden snapshots generated from the *current* generator output **before** refactoring, then held. This is the first issue in the milestone. |
| Simulated availability makes recommendations feel arbitrary | High | Mandatory disclosure banner. Honest is better than confident. |
| Seat map inaccessible by keyboard | High if unplanned | Grid semantics and roving focus designed up front, axe in CI, a keyboard-only Playwright test |
| Quality encoded in gold-vs-grey only | High | Two signals per state, enforced in review and by a Vitest assertion on accessible names |
| "Reserve" read as "held" | High, serious | Exact copy specified above. This is a trust issue, not a wording preference. |
| Booking link is an open redirect | Low, serious | Host allowlist validated at render time, not just at seed time |
| Scoring latency blows the budget on IMAX layouts | Medium | Benchmark test as a blocking check; `to_thread`; Redis memoisation |
| Group logic returns non-contiguous seats | Medium, severe | Explicit contiguity test; a returned option must be bookable as-is |
| Mobile seat map unusable at 375px | High | Pan-and-zoom rather than shrinking; 44px targets; tested on a real device |

## Done when

**A user can pick a showtime, get ranked seats with scores, and land on the theatre's booking
page.**

Demonstrated end to end, on a phone, by a human:

1. Open a film page, pick a showtime at a seeded auditorium
2. Enter a party of two, request recommendations
3. See golden seats highlighted with visible scores and a factor breakdown
4. See the availability confidence disclosed
5. Select the top option and choose "Book online"
6. Land on the theatre's real booking page for that showtime
